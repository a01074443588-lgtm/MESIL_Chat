# **MESIL Chat — 돌봄 현장의 보고를 다음 업무로 잇는 AI 협업 도구**

**MESIL Chat(메실챗)은 직원이 채팅·사진·손글씨·음성으로 남긴 보고를 AI가 읽고 정리하고, 사람이 원문을 확인해 인수인계와 기록에 활용하는 돌봄 협업 서비스입니다.**

“분명히 보고했는데, 그 뒤에는 어떻게 됐지?”라는 질문에서 출발했습니다. 새 기록을 한 번 더 쓰게 하기보다, 이미 남긴 보고를 찾아 어르신의 변화와 후속조치를 함께 살펴볼 수 있게 돕습니다.

[MESIL Chat 사용하기](https://chat.silvermedical.kr) · [처음 사용하는 분을 위한 안내](#23-이용자용-가이드) · [공개 소스](https://github.com/a01074443588-lgtm/MESIL_Chat/tree/challenge-final-20260915)

> 공개 체험에는 가상의 인물과 상황으로 만든 합성자료를 사용합니다. AI 결과는 확인을 돕는 초안이며, 의료적 판단이나 공식 기록을 자동으로 확정하지 않습니다. 아래 내용은 2026년 9월 17일까지 확인한 기능과 검증 자료를 기준으로 작성했습니다.

## **1. 팀 기본 정보**

### **1.1 기관 정보**

**실버메디컬복지센터 노인요양원&재가**는 장기요양 현장에서 어르신을 돌보고 직원의 보고·인수인계·기록 업무를 운영하는 기관입니다.

MESIL Chat은 시설 운영 책임자가 현장의 문제를 정의하고, 사회복지 업무 담당자가 실제 업무 흐름과 사용성을 검토하며 발전시킨 서비스입니다. 목표는 직원이 보고를 더 많이 작성하게 하는 것이 아니라, 이미 작성한 보고를 다음 담당자가 놓치지 않고 활용할 수 있게 하는 것입니다.

## **2. AI 솔루션**

### **2.1 문제 정의**

돌봄 현장의 보고는 책상 앞에서만 만들어지지 않습니다. 어르신을 도우면서 짧게 남긴 대화, 손으로 적은 메모의 사진, 말로 전달한 상황처럼 여러 형태로 쌓입니다. 교대하는 직원이나 기록을 정리하는 사회복지사는 이 자료를 다시 찾아 읽어야 합니다.

예를 들어 “평소보다 식사를 적게 하셨다”는 보고만으로는 이후 상태를 알 수 없습니다. 누가 다시 확인했는지, 어떤 조치를 했는지, 나중에 어떻게 달라졌는지까지 함께 봐야 합니다. 대화가 많아질수록 그 연결을 사람이 기억하고 찾아내는 부담도 커집니다.

MESIL Chat이 해결하려는 문제는 다음 세 가지입니다.

- **찾는 부담:** 어르신과 기간에 맞는 보고를 긴 대화에서 다시 찾아야 합니다.
- **옮겨 적는 부담:** 사진·손글씨·음성으로 받은 내용을 문장으로 다시 정리해야 합니다.
- **확인하는 부담:** AI가 정리해 주더라도 원문과 대상자를 확인할 수 없으면 기록에 활용하기 어렵습니다.

주요 이용자는 현장에서 보고하는 돌봄 직원, 인수인계를 받는 동료, 기록을 검토하는 사회복지사와 관리 책임자입니다. 익숙한 채팅을 출발점으로 삼아 이들의 업무를 연결합니다.

### **2.2 AI 솔루션 소개**

#### **솔루션 개요**

MESIL Chat에서는 **보고하기 → 필요한 내용 찾기 → 원문 확인하기 → 사람이 수정·승인하기**가 하나의 업무 흐름으로 이어집니다.

일반 채팅방은 직원끼리 보고하고 상의하는 공간입니다. `MESIL AI 도움방`은 직원마다 따로 제공되는 개인 AI 대화방입니다. 일반적인 업무 질문에는 설명을 제공하고, 어르신 기록을 묻는 질문에는 그 직원이 접근할 수 있는 일반방의 기록을 찾아 근거와 함께 답합니다.

`AI 돌봄 브리핑`에서는 보고된 변화와 후속 확인 내용을 살펴보고, `기록 검토`에서는 원본과 판독문을 대조하며 필요한 내용을 검토합니다. AI 도움방에 질문했다는 이유만으로 공식 기록이나 업무 항목이 자동 생성되지는 않습니다.

#### **솔루션 사용 링크**

| 구분 | 링크 또는 안내 |
|---|---|
| 솔루션 실행 링크 | [MESIL Chat 공개 체험](https://chat.silvermedical.kr) |
| 소스코드 또는 결과물 원본 | [공식 저장소의 공개 소스](https://github.com/a01074443588-lgtm/MESIL_Chat/tree/challenge-final-20260915) |
| 데모 영상(선택) | 제작 예정입니다. 서버 파일명은 `mesil-chat-ai-challenge-final-demo.mp4`로 지정했으며, 현재는 공개 링크가 없습니다. 제작·검증·업로드가 끝나면 이 항목에 링크를 추가합니다. |
| 테스트 계정(선택) | 담당자가 권한이 제한된 합성자료용 계정을 개별 안내합니다. 계정 비밀번호는 공개 문서에 싣지 않습니다. |

공개 사이트와 소스 저장소는 업데이트 시점이 다를 수 있습니다. 위 소스 링크는 9월 15일 공개본이며, 9월 17일까지 공개 서비스에 반영된 손글씨·음성 교정과 운영 설정 수정이 모두 포함됐다는 뜻은 아닙니다.

#### **설치 및 실행 방법**

**직접 체험할 때는 설치가 필요하지 않습니다.** PC·휴대전화·태블릿의 최신 브라우저에서 실행 링크를 열고 안내받은 계정으로 로그인하세요. 통화와 녹음에는 마이크·카메라 권한이 필요합니다.

Chat은 GitHub나 `/downloads`에서 Android 설치파일(APK)을 제공하지 않습니다. 모바일에서는 브라우저로 접속하며, 지원하는 브라우저에서는 홈 화면에 추가한 웹앱으로 사용할 수 있습니다.

**개발자·운영자의 자체 설치:** Docker Desktop과 Docker Compose를 준비한 뒤 [공개 소스 ZIP](https://github.com/a01074443588-lgtm/MESIL_Chat/archive/6648c04d00be506b7e8c3697eff382ae362adadd.zip)을 새 폴더에 풀어 사용합니다. 다음 명령은 공개 소스의 `docker-compose.yml`과 `.env.example`이 있는 루트 폴더에서 Windows PowerShell로 실행합니다.

```powershell
if (-not (Test-Path .\docker-compose.yml) -or -not (Test-Path .\.env.example)) {
    throw "공개 소스의 루트 폴더에서 실행하세요."
}
if (Test-Path .\.env) { throw "기존 .env가 있습니다. 새 설치 폴더인지 확인하세요." }
Copy-Item .\.env.example .\.env
notepad .\.env
```

열린 파일에서 `POSTGRES_PASSWORD`와 `BOOTSTRAP_ADMIN_PASSWORD`를 서로 다른 새 비밀번호로 입력하고, `BOOTSTRAP_ADMIN_USERNAME`도 직접 정한 뒤 저장합니다. 실제 운영 계정과 비밀번호를 복사하지 않습니다.

현재 위치는 계속 공개 소스의 루트 폴더입니다.

```powershell
docker compose -p mesil_public_demo up -d --build
if ($LASTEXITCODE -ne 0) { throw "기동에 실패했습니다. 다음 단계로 진행하지 마세요." }
docker compose -p mesil_public_demo ps
```

[공개 설치 안내의 준비 확인 절차](https://github.com/a01074443588-lgtm/MESIL_Chat/blob/6648c04d00be506b7e8c3697eff382ae362adadd/docs/PUBLIC_INSTALL.md)에 따라 최대 2분 안에 health 응답이 정상인지 확인하고, `http://localhost:18080`에서 직접 정한 관리자 계정으로 로그인합니다. 시간이 지나도 준비되지 않으면 같은 안내에 있는 Backend 로그 확인 단계로 돌아갑니다.

새 설치는 빈 데이터베이스로 시작합니다. 체험 서버의 계정·대화·첨부는 포함되지 않습니다. 기본 로그인·채팅과 AI 준비는 별개이며, AI에는 내부 모델 실행 도구인 Ollama와 음성 인식 서비스를 따로 구성해야 합니다. 공개 소스에는 AI 모델 파일이나 외부 AI 계정이 들어 있지 않습니다.

| 업무 질문과 기록 질문하기 | 개인별 `MESIL AI 도움방` | 일반 설명과 기록을 사용한 답변을 구분하고, 기록 답변에는 대상자·조회 기간·근거를 표시합니다. |
| 사진과 말을 글로 활용하기 | 사진·손글씨·문서 판독, 음성 받아쓰기와 손글씨·음성 최종문 비교 | 원본 OCR, 음성 전사본, 최종 제안을 나란히 보고 이름·숫자·시간과 중요한 차이를 확인합니다. |
| 인수인계에 필요한 내용 찾기 | `AI 돌봄 브리핑`, `기록에 질문하기` | 관찰·조치·후속 보고를 원문과 함께 확인합니다. |
| 기록을 검토하고 활용하기 | 담당자의 판독문 수정, 기록 초안 검토·승인 | AI 제안을 그대로 확정하지 않고 사람이 수정하거나 사용하지 않을 수 있습니다. |
| 말과 화면으로 바로 상의하기 | 1:1 음성·영상통화 | 두 기기의 마이크·카메라 권한과 연결 상태를 확인합니다. 다자 통화는 현재 보완 중입니다. |

#### **AI 활용 내용**

| 구분 | 내용 |
|---|---|
| 사용한 AI 도구·모델 | 내부 Ollama 텍스트 모델, 이미지 판독용 시각·언어 모델(VL), faster-whisper 음성 인식(STT)을 사용합니다. 최근 공개 검증에서 텍스트 응답은 `qwen3.8-27b:q5_k_m`, 음성 인식은 `large-v3-turbo`로 확인했습니다. 이미지 판독의 기존 합성 검증 모델은 `qwen3-vl:8b-instruct`입니다. |
| AI가 담당하는 기능 | 대화 요약, 기록 질문에 대한 근거 중심 답변, 일반 업무 설명, 사진·손글씨 판독, 음성 받아쓰기를 보조합니다. |
| AI를 활용한 이유 | 같은 내용을 서로 다른 표현으로 보고하고, 글·사진·음성으로 남기기 때문에 단어 검색만으로는 업무 흐름을 파악하기 어렵습니다. AI가 먼저 읽고 정리하면 직원은 원문 확인과 후속 판단에 집중할 수 있습니다. |
| AI가 없었다면 어려웠던 부분 | 여러 보고를 일일이 읽어 시간 순서와 대상자를 대조하고, 사진과 음성의 내용을 직접 옮겨 적어야 합니다. |

OCR은 이미지의 글자를 읽는 기능, VL은 이미지와 글의 내용을 함께 이해하는 모델, STT는 말을 글로 바꾸는 기능을 뜻합니다. 모델 선택값과 실제 응답 모델은 구분하며, AI가 호출되지 않은 ‘기록 없음’ 결과를 모델 답변으로 세지 않습니다. 텍스트의 위 이름은 서버의 로컬 태그이며, 공식 모델 출처나 이용허가를 증명하는 명칭은 아닙니다.

#### **(선택)AI 성능 개선 시도**

1. **답변보다 먼저 근거를 확인했습니다.** 직원의 접근권한 안에서 자료를 찾고, 선택된 근거와 답변의 대상자가 맞는지 검사합니다. 동명이인을 이름만으로 합치거나 긴 답변에서 뒤 대상자를 빠뜨리는 문제도 회귀시험으로 보완했습니다.
2. **‘기록 없음’과 ‘AI 실패’를 구분했습니다.** 조회한 기간에 상담 근거가 없을 때는 그 범위를 알려줍니다. 모델 연결이나 생성이 실패한 경우에는 기록이 없었다고 바꿔 말하지 않습니다.
3. **손글씨와 음성을 함께 쓰되 근거를 남겼습니다.** 전체 읽기에서 음성이 명확하면 문장 내용은 음성 전사본을 우선하고, OCR은 원본의 행과 형태를 확인하는 근거로 함께 보여 줍니다. 양쪽에 정확한 표준용어나 등록 별칭이 있을 때만 장기요양 단어장의 표준 표현을 사용하며, 이름·시간·수량·약명·진단·완료 여부처럼 중요한 차이는 직원이 따로 확인합니다. 최종문 안에 의미를 잃는 임의의 확인용 문구를 넣어 대신하지 않습니다.

### **2.3 이용자용 가이드**

#### **먼저, 평소처럼 보고해 보세요**

안내받은 합성자료용 계정으로 로그인하고 본인에게 열린 일반 채팅방을 선택하세요. PC에서는 입력창에 글을 적거나 `Ctrl+V`로 붙여넣을 수 있습니다. 캡처 이미지를 붙이면 바로 보내지 않고 첨부 대기목록에 먼저 나타납니다. 파일명과 미리보기를 확인한 다음 전송하세요. 마음이 바뀌면 전송 전에 첨부를 취소할 수 있습니다.

휴대전화에서는 첨부 버튼으로 사진이나 파일을 선택하면 됩니다. 브라우저마다 파일 붙여넣기 지원 범위가 다르므로 붙여넣기가 안 되면 같은 첨부 버튼을 사용하세요. 체험 중에는 실제 직원·어르신의 사진이나 기록 대신 제공된 합성자료만 사용합니다.

#### **“그 뒤에 어떻게 됐나요?”를 원문과 함께 확인해 보세요**

보고가 있는 방에서 검색을 열고, 화면에 자료가 있는 기간과 확인할 내용을 선택하세요. 요약 기능을 실행하면 보고의 흐름을 빠르게 살펴볼 수 있습니다. 문장에 붙은 **근거**를 눌러 누가 어떤 내용을 보고했는지 원래 대화로 돌아가 보세요.

`AI 검색 요약`과 `기록 기반 요약`은 서로 다른 처리 결과입니다. 넓은 검색에서는 AI 생성 결과가 검증을 통과하지 못해 기록 기반 요약이 나올 수 있습니다. 이 경우에도 근거를 직접 확인할 수 있으며, AI 요약이 성공한 것으로 표시하지 않습니다.

#### **내 AI 도움방에서 두 가지 질문을 해 보세요**

방 목록에서 `MESIL AI 도움방`을 여세요. 모든 직원이 함께 보는 공용방이 아니라 **로그인한 직원의 개인 AI 대화방**입니다.

먼저 일반적인 돌봄 질문을 입력해 보세요.

> 어르신 기저귀 케어 시 왜 가림막을 쳐야 하나요?

존엄성과 사생활 보호처럼 업무에 참고할 설명을 확인할 수 있습니다. 이런 질문에는 내부 돌봄기록을 임의로 붙이지 않습니다. 시설의 계약 내용이나 최신 평가지표처럼 AI가 확인하지 못한 정보는 별도 자료가 필요하다는 안내를 따르세요.

다음에는 화면에 있는 합성 어르신과 기록 기간을 확인한 뒤 질문하세요.

> 어르0002의 최근 7일 상태와 근거를 알려줘.

답변에서 **대상자와 실제 조회 기간을 먼저 읽고**, 근거를 열어 원문을 확인하세요. 예시의 `어르0002`는 합성 코드입니다. 해당 계정에 보이는 다른 합성 대상과 자료 기간을 사용할 수도 있습니다. 자료가 과거 날짜에 있다면 ‘최근 7일’ 대신 그 날짜를 지정해야 합니다.

상담 기록을 찾지 못했다는 답변은 상담 자체가 없었다는 뜻이 아닙니다. **선택한 범위에서 확인되는 기록이 없다는 뜻**입니다. 안내된 기간을 확인하고, 필요하면 사용자가 직접 다른 기간을 선택해 다시 찾아보세요.

#### **사진과 음성을 ‘확인할 수 있는 글’로 바꿔 보세요**

제공된 합성 손글씨 이미지나 음성 첨부를 열어 판독이 완료됐는지 확인하세요. 화면에서 **원본 OCR**, **음성 전사본**, **최종 제안**을 나란히 비교해 보세요. 전체 읽기에서 음성이 명확하면 말이 되는 문장 내용은 음성 전사본을 중심으로 제안하고, OCR은 원본의 행과 글자 형태를 확인하는 데 사용합니다. 단어장의 표준 표현도 원본 OCR이나 음성에 정확한 용어·등록 별칭 근거가 있을 때만 적용합니다. 특히 이름, 숫자, 날짜, 약 이름은 사람이 확인해야 합니다.

손글씨 검토 화면의 `말로 고치기`를 사용할 때는 마이크를 허용한 뒤 바로잡을 내용을 말하고, 받아쓰기와 원래 판독문의 차이를 확인하세요. 최종문을 직원이 직접 고친 뒤 같은 근거에서 읽기 방식을 바꾸거나 같은 음성을 다시 선택해도 그 수정문을 유지합니다. 다른 메시지·이미지·음성으로 이동하면 이전 미저장 문장을 가져가지 않습니다. 녹음·판독이 준비되지 않았다면 상태 안내에 따라 재시도합니다. AI 도움방에 첨부 내용을 물을 때도 판독이 끝나지 않은 자료를 이미 읽었다고 간주하지 않습니다.

#### **기록으로 쓰기 전에 마지막 확인은 사람이 합니다**

권한이 있는 계정에서는 `AI 돌봄 브리핑`과 `기록 검토`를 열 수 있습니다. 원문, 대상자, 날짜, 조치 내용을 확인하고 틀린 판독문이나 초안을 수정하세요. 맞지 않는 제안은 사용하지 않아도 됩니다. 최종 승인 권한이 있는 담당자의 확인을 거쳐 기록을 활용합니다.

심사 체험에서는 원문 확인과 편집 흐름까지만 살펴보고, 승인·확정은 담당자가 안내한 별도 합성 시나리오에서만 실행하세요. AI 답변을 받는 것과 공식 기록을 승인하는 것은 별개의 작업입니다.

#### **직접 상의할 때는 1:1 통화를 사용하세요**

일반 채팅방에서 통화할 동료 한 명을 선택하고 음성 또는 영상통화를 요청하세요. 양쪽 모두 화면을 켜고 마이크·카메라 사용을 허용합니다. 통화를 마치면 종료 후 채팅으로 돌아옵니다.

현재 3인 이상 통화는 일부 참가자가 늦게 접속하는 상황을 보완 중이므로 체험은 1:1을 권장합니다. 네트워크 환경에 따라 연결이 제한될 수 있으며, 잠금화면 통화 수신이나 모든 외부망 연결을 보장하지 않습니다.

### **2.4 관리자용 가이드**

#### **구성과 설치 범위**

화면은 React와 Next.js 호환 구조 및 Vinext·Vite로 구성하고, FastAPI가 인증·채팅·AI 요청을 처리합니다. WebSocket은 새 메시지와 통화 신호를 전달합니다. PostgreSQL에 업무 데이터를 저장하고, 첨부파일은 별도 저장소에서 관리합니다. AI는 내부 Ollama와 음성 인식 서비스로 연결합니다.

자체 설치는 위의 공개 소스와 [상세 설치 안내](https://github.com/a01074443588-lgtm/MESIL_Chat/blob/6648c04d00be506b7e8c3697eff382ae362adadd/docs/PUBLIC_INSTALL.md)를 사용하세요. 공개 소스의 로컬 Compose 구성과 실제 서비스의 운영 구성은 같지 않습니다. 다른 기관에 적용할 때는 그 기관의 계정·권한·HTTPS·AI 처리환경을 별도로 준비해야 합니다.

#### **운영자가 확인할 일**

1. **계정과 접근권한:** 직원에게 필요한 방만 허용하고 퇴사·이동 시 접근권한을 점검합니다. 개인 AI 도움방을 관리자에게 공개된 업무방으로 취급하지 않습니다.
2. **AI 준비 상태:** 모델 선택값뿐 아니라 실제 응답 모델과 음성 인식 준비 상태를 확인합니다. 모델 적재와 동시에 실행하는 작업에 따라 응답시간이 달라질 수 있습니다.
3. **실패 안내:** 기록이 없는 경우, 조회 오류, AI 생성 실패를 구분합니다. 실패를 숨기기 위해 조회 범위나 직원의 권한을 넓히지 않습니다.
4. **백업과 복구:** DB 백업과 첨부파일 백업을 각각 준비합니다. 공개 패키지에는 자동 백업·복원 도구가 없으며, Docker 볼륨에 저장된다는 사실만으로 백업이 되는 것은 아닙니다. 실제 복원 시험을 통과한 절차를 사용합니다.
5. **운영 정책:** 개인정보 안내, 보유기간, 삭제 절차, 로그·백업 접근권한을 기관 기준으로 정합니다. 저장소에 실제 설정 파일이나 계정·토큰을 올리지 않습니다.

공개 소스의 Android 관련 파일은 참고 코드이며 완성된 앱 빌드 프로젝트가 아닙니다. 모바일 브라우저 이용을 기본으로 안내합니다. 배포·모델 변경은 서비스 이용이 적은 시간에 복구 이미지와 데이터 보존 기준을 준비하고 진행합니다.

## **3. 임팩트 계획서**

### **3.1 현장 적용 결과**

현장 업무에서 나온 요구를 바탕으로, 보고를 남기는 직원과 확인·기록하는 담당자의 동선을 연결하는 서비스를 구현했습니다. 공개 체험 환경에서는 합성자료를 사용해 로그인·채팅·근거 열기·판독 결과 확인·기록 질문 등의 흐름을 검증했습니다.

| 확인한 변화 | 확인 범위 |
|---|---|
| 사진·음성을 원본·전사본·최종 제안으로 함께 볼 수 있음 | 합성 이미지·음성으로 전체 읽기, 단어장 표준화, 직원 직접 수정문 보존과 원본 유지를 확인했습니다. |
| 어르신 질문의 답변에서 원문으로 돌아갈 수 있음 | 합성 기록을 대상으로 대상자·기간·근거 연결을 확인했습니다. |
| 기록 없음과 처리 실패를 구분할 수 있음 | 상담 기록이 없는 기간을 지정한 공개 서비스 검증에서 정상 ‘기록 없음’ 안내를 확인했습니다. |
| PC와 모바일에서 같은 업무 흐름을 확인할 수 있음 | PC 1920×1080과 모바일 390×844 화면의 주요 조작부와 가로 넘침을 확인했습니다. |
| 공개 Chat에서 잠금화면 알림을 켤 수 있음 | Web Push 활성화와 공개키 설정을 확인했습니다. 실제 기기 수신 여부는 브라우저·운영체제 권한에 따라 별도로 확인해야 합니다. |

이 결과는 **기능과 업무 흐름의 검증**입니다. 실제 직원의 업무시간이 몇 퍼센트 줄었다거나 기록 누락·사고가 감소했다는 정량적 성과를 뜻하지 않습니다. 실제 현장 효과는 참여자 동의와 평가 기준을 마련한 뒤 별도로 측정할 예정입니다.

### **3.2 시행착오와 개선**

| 시행착오 | 개선한 내용 | 남아 있는 한계 |
|---|---|---|
| 특정 어르신의 상태 질문을 일반 설명으로 처리함 | 대상·기간·기록 문맥을 살펴 기록검색으로 연결하고 회귀시험을 추가했습니다. | 새 표현에서는 답변의 조회 기간과 근거를 계속 확인해야 합니다. |
| 긴 답변에서 대상자가 빠지거나 동명이인이 합쳐짐 | 검증된 대상 식별자로 근거를 묶고, 출력 길이를 줄여도 대상 표시를 보존하도록 보완했습니다. | 원본의 대상 연결이 불확실하면 확인이 필요하다고 표시합니다. |
| 상담 근거가 없는 결과를 AI 실패처럼 안내함 | 정상 기록 없음과 실제 처리 실패를 구분했습니다. | 기록이 없다는 안내로 실제 사건의 부재를 단정할 수 없습니다. |
| 음성 인식 설정과 실제 실행 상태가 다를 수 있음 | 중앙 설정과 실제 모델·실행 장치를 확인하고 완료 후에도 준비 상태를 재검사합니다. | 물리 마이크와 다른 통화 앱을 동시에 쓰는 환경의 품질은 추가 확인이 필요합니다. |
| OCR 행과 음성 문장 배치가 달라 말이 되는 전사보다 깨진 OCR 조각이 최종문에 남음 | 음성이 명확한 전체 읽기는 음성 문장 순서를 사용하고, 정확한 단어장 용어·별칭만 근거와 함께 표준화하도록 보완했습니다. | 음성 품질이 낮거나 중요한 사실이 충돌하면 원문을 직접 확인해야 합니다. |

검색 결과 AI 요약은 넓은 범위에서 검증을 통과하지 못해 기록 기반 요약으로 전환될 수 있습니다. 다자 통화의 늦은 참가·재접속도 보완 중입니다. 통화 중계를 위한 TURN은 현재 구성되지 않아 모든 외부망 조합을 보장하지 않습니다. 새 메시지 Web Push는 공개 Chat에서 활성화했지만, 잠금화면 실제 수신은 사용자의 알림 허용과 기기·브라우저·운영체제 상태에 따라 달라질 수 있습니다.

### **3.3 향후 계획 및 임팩트 확산**

1. **현장 효과 측정:** 같은 업무에서 보고를 찾는 시간, 판독문 수정량, 후속 확인의 누락 여부를 측정합니다. 합성시험과 실제 현장 결과를 구분해 공개합니다.
2. **사용환경 안정화:** 넓은 검색 요약, 다자 통화와 다양한 마이크·통신환경을 개선하고 실제 직원의 사용 경험으로 점검합니다.
3. **다른 기관에 적용:** 합성자료로 먼저 체험한 뒤 기관의 권한·서식·보유정책에 맞춰 도입할 수 있도록 설치·운영 안내를 다듬습니다.

장기요양 업무시스템과의 연계는 향후 과제입니다. 현재 기록 연계 미리보기를 SMCODI나 공단에 공식 기록을 실제 전송하는 기능으로 소개하지 않습니다.

### **4.5 개인정보·AI 윤리 항목**

**1) 어떤 개인정보를 모으고, 어디에 쓰고, 어디로 보내나요?**

서비스는 직원 계정과 방 참여정보, 메시지, 첨부파일, 판독문, 로그인·읽음 이력을 다룹니다. 실제 업무에 사용하면 여기에 어르신의 관찰·상담·건강 관련 내용이 포함될 수 있습니다. 계정·권한 관리, 보고 공유, 원문 확인과 기록 검토에 쓰며 기관이 관리하는 DB와 첨부 저장소에 보관합니다.

공개 체험의 업무자료는 합성자료입니다. 최근 검증에서는 텍스트·이미지·음성 AI를 내부 서비스로 처리했고 외부 AI 전송은 관측되지 않았습니다. 다만 웹 접속에는 Cloudflare, 통화 연결에는 외부 STUN 주소 확인 서비스가 관여할 수 있습니다. 내부 AI 사용을 인터넷 통신 전체가 없다는 뜻으로 설명하지 않습니다. 외부 AI 연결 기능을 별도로 켜는 경우에는 전송 범위와 처리 근거를 다시 확인해야 합니다.

**2) 개인정보 수집·활용의 동의 또는 처리 근거는 무엇인가요?**

공개 체험용 업무자료는 실제 기록의 이름만 바꾼 자료가 아니라 가상의 인물과 상황으로 만든 자료를 사용합니다. 다만 접속·인증정보는 별도로 생기므로 이를 포함한 개인정보 안내와 보유기준이 필요합니다. 실제 기관자료를 사용하는 경우의 동의·처리 근거와 민감정보 처리 범위는 기관이 확인해야 하며, 기술 구현이나 합성시험만으로 법적 적합성이 확인됐다고 주장하지 않습니다.

**3) 개인정보 처리와 AI 사용 사실을 어떻게 알리나요?**

`MESIL AI 도움방`, `AI 돌봄 브리핑`, `AI 검색 요약`처럼 AI가 관여하는 기능을 표시합니다. 일반 업무 설명, 기록을 사용한 답변, AI 생성에 실패해 표시한 기록 기반 요약을 구분하며, 이용자 가이드에서 원문 확인 방법과 합성자료 체험 범위를 안내합니다. 기관 운영 시에는 수집 항목·외부 처리·보유 및 삭제·문의 방법을 담은 개인정보처리방침과 AI 활용 안내를 마련해야 합니다. 이 README가 그 절차를 대신하지 않습니다.

**4) AI가 틀렸을 때 사람이 확인하고 고칠 수 있나요?**

기록 답변의 근거를 눌러 원문으로 돌아가고, 사진·음성의 판독문을 원본과 비교할 수 있습니다. 권한이 있는 담당자는 판독문과 기록 초안을 수정하거나 제안을 사용하지 않을 수 있으며, 최종 승인은 담당자가 수행합니다. AI 도움방의 답변을 받은 것만으로 공식 기록이 확정되거나 외부 업무시스템으로 전송되지는 않습니다.

**5) AI 사용으로 발생할 수 있는 피해를 어떻게 줄이나요?**

직원이 볼 수 있는 자료만 기록검색에 사용하고, 답변과 근거의 대상자를 검사합니다. 불확실한 대상은 확인이 필요하다고 표시하며, 자료가 없는 경우와 AI 오류를 구분합니다. 판독이 끝나지 않은 첨부를 읽었다고 답하지 않도록 제한하고, 진단·투약·처치·위험평가를 AI가 자동 확정하지 않도록 합니다.

이 장치가 모든 오류를 없애지는 않습니다. 특히 숫자·약 이름·시간·대상자는 직원이 확인하고, 의료적 판단과 최신 제도 해석은 담당 전문가와 공식 자료에 따라야 합니다. 원문 근거를 열어 확인하고 잘못된 결과를 채택하지 않을 수 있는 흐름을 기본으로 삼았습니다.
