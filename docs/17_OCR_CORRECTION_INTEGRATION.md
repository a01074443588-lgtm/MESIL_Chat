# OCR 교정 이력 통합

기준일: 2026-07-28

## 목적

손글씨 OCR의 최초 판독문을 바꾸지 않고 보존하면서, 담당자가 확인한 수정만
다음 판독의 교정 후보에 반영한다. 이 기능은 OCR 모델 자체를 교체하는 기능이
아니며, 반복되는 오인을 사람 확인 기반으로 줄이는 보조 기능이다.

참조한 독립 실험은 `D:\Projects\SMCODI_OCR_CORRECTION_LAB`이다. 실험실의
SQLite DB·원본 이미지·개인정보는 이 프로젝트로 복사하지 않았다.

## 적용 원칙

1. 최초 OCR 원문은 `original_extracted_text`에 한 번만 저장하고 재판독이나
   검토로 덮어쓰지 않는다.
2. 담당자의 모든 선택은 `staff_hub_ocr_correction_events`에 추가 방식으로
   기록한다. 과거 이벤트는 수정하거나 삭제하지 않는다.
3. 다음 OCR에서는 같은 기관에서 확정된 과거 사례의 OCR 문자열, 주변 문맥,
   작성자, 이미지 수치 특징의 유사도를 후보 점수에 반영한다.
4. 이름·시간·숫자·약·신체 부위·사건 내용은 중요 항목으로 표시하고
   자동으로 바꾸지 않는다.
5. 일반 단어를 포함한 모든 후보는 첫 운영 버전에서 제안만 한다.
6. `원문 그대로 확정`, `선택 후보로 확정`, `직접 수정문 확정`만 학습한다.
   `확인 필요로 남기기`는 이벤트만 기록하고 다음 후보 학습에는 쓰지 않는다.
7. 후보를 누르는 것만으로는 DB가 바뀌지 않는다. 담당자가 확정 버튼을 눌러야
   교정 이벤트가 저장된다.

## 화면 흐름

1. `업무함 → 처리할 대화`에서 이미지 보고를 연다.
2. `최초 OCR 원문`에서 바뀌지 않는 판독 원문을 확인한다.
3. 과거 확정 사례가 있으면 `교정 후보`에서 차이, 근거 수, 신뢰도와
   중요 항목 경고를 확인한다.
4. 다음 중 하나를 선택한다.
   - 원문 그대로 확정
   - 후보를 눌러 교정문에 넣고 선택 후보로 확정
   - 교정문을 직접 수정하고 직접 수정문 확정
   - 판단하기 어려우면 확인 필요로 남기기
5. 확정 전까지 아래 AI 업무기록 정리는 진행하지 않는다.

## 데이터 구조

### 기존 판독 테이블에 추가한 열

- `attachment_text_extractions.original_extracted_text`
  - 최초 OCR 원문
- `attachment_text_extractions.visual_signature`
  - 원본 이미지를 복제하지 않고 계산한 숫자 특징

### 추가형 이벤트 테이블

- `staff_hub_ocr_correction_events`
  - 기관, 판독, 첨부, 메시지, 작성자, 검토자
  - 선택 종류와 확정 여부
  - 최초 원문과 확정 교정문
  - 토큰별 교정 쌍과 중요 내용 종류
  - 문맥, OCR 제공자·모델, 이미지 수치 특징
  - 선택한 후보 식별자와 생성시각

마이그레이션은 `018_ocr_correction_events`이며 기존 테이블을 다시 만들지 않는
추가형 변경만 사용한다.

## API

기존 이미지 판독 검토 API를 확장했다.

`PATCH /api/attachments/{attachment_id}/text-extraction`

지원 선택:

- `keep_raw`
- `apply_candidate`
- `direct_edit`
- `needs_review`

서버는 `apply_candidate` 요청의 후보 식별자가 현재 화면에 실제로 제시된
후보인지 다시 확인한다. 화면에서 임의 값을 보내 교정 이력으로 학습시키는
요청은 거부한다.

## 이미지 유사도의 현재 범위

현재 OCR 결과에는 글자별 위치 상자가 없으므로 이미지 유사도는 페이지 전체에서
계산한 작은 수치 특징을 낮은 가중치로 사용한다. 이는 같은 양식이나 촬영 상태를
보조적으로 비교하는 수준이며, 특정 글씨 영역이 같다고 보장하지 않는다.
향후 OCR 모델이 글자·줄 위치를 제공할 때 영역별 특징으로 교체한다.
