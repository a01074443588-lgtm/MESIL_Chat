# Nemotron 3 Ultra 550B 전환 및 검증 기록

작성일: 2026-07-29

## 적용 결론

- NVIDIA 1순위 호출 모델을 `nvidia/nemotron-3-ultra-550b-a55b`로 변경했다.
- 기존 `Qwen3.6 35B → Gemma` 로컬 대체 경로와 근거 검증은 유지했다.
- Ultra 결과가 크다고 해서 자동 승인하지 않는다. 원문에 없는 이름·시간·수치·위험 표현·조치를 만들거나 JSON 구조가 맞지 않으면 결과를 폐기하고 안전한 대체 경로를 사용한다.
- 따라서 이번 변경은 **Ultra를 가장 먼저 호출하는 전환**이며, **Ultra 응답을 무조건 화면에 표시하는 전환**은 아니다.

## API 호환 설정

- Chat Completions API 사용
- `response_format={"type":"json_object"}` 적용
- `chat_template_kwargs={"enable_thinking": false}` 적용
- 온도 `0` 적용
- 응답 제한시간 `120초` 적용
- 408, 429, 5xx 및 일시적 연결 오류에 한해 1회 재시도
- 어르신 표기는 외부 모델 호출 전에 `RESIDENT_001` 형식으로 바꾸고, 검증 통과 후 원래 가명으로 복원
- `시설(가명)001`과 `주간-어르신-01(가명)` 형식을 모두 외부 호출 전에 치환
- 기록별 정리뿐 아니라 일반 대화·기간 요약에도 원문에 없는 어르신·수치·위험 표현·부정 사실 반전 검증 적용
- 6,000자를 넘는 비정상적으로 긴 결과는 중간에서 잘라 쓰지 않고 폐기

## 해석

Ultra 550B는 Nano 30B보다 큰 모델이지만 이번 장기요양 기록 사례에서는 사실 보존이 자동으로 좋아지지 않았다. 특히 의료·돌봄 문맥을 그럴듯하게 보완하면서 원문에 없는 진단성 표현이나 조치를 추가할 위험이 확인됐다.

그러므로 현재 안전한 운영 구조는 다음과 같다.

1. Ultra 550B를 먼저 호출한다.
2. JSON 구조와 근거 번호를 검사한다.
3. 원문에 없는 이름·시간·수치·위험 표현·부정 사실 반전이 있는지 검사한다.
4. 통과한 결과만 사용한다.
5. 실패하면 로컬 모델 또는 근거 기반 안전 정리로 전환한다.
6. 공식 기록 사용 전에는 담당자가 원문을 확인한다.
