# Web Push 알림 복구와 제한된 전송 경로

## 수정한 범위

- 알림 등록 실패를 ‘이 발표환경에서는 제공하지 않음’으로 표시하던 문제를 바로잡고 실제 오류와 재연결 버튼을 구분합니다.
- 기존 브라우저 구독과 현재 로그인 사용자가 맞지 않는다는 **정확한 403 오류**에 한해, 사용자가 ‘이 기기 알림 다시 연결’을 누르면 해당 브라우저 구독을 해제하고 새 구독을 등록합니다. 다른 사용자 구독을 가져오거나 서버 소유권을 이전하지 않습니다. 일반 권한 거부, 구독 해제 실패, 동일 주소 재발급은 우회하지 않습니다.
- 자동 상태 조회에서는 구독을 임의 교체하지 않습니다. 등록 성공 뒤 시험 전송이 실패하면 등록과 전달 상태를 구분해 알립니다.
- 서버의 내부망 격리를 유지하면서 Google FCM으로 시험 알림을 전송할 수 있도록 별도의 제한 중계 경로를 구성했습니다. Backend 소스와 DB 스키마는 변경하지 않았습니다.

## 확인된 결과와 한계

공개 Chat의 문제 Android 휴대전화 1대에서 등록 거부 → 명시적 재연결 → 새 구독 등록 HTTP 201 → 시험 전송 HTTP 202를 확인했습니다. 사용자가 시험 알림 수신·소리·알림 목록 표시를 확인했습니다. 이는 시험 알림 1종과 해당 기기의 확인 결과이며, 모든 기기·통신망·장시간 절전·일반 업무 메시지의 모든 상황이나 통화 수신을 검증한 결과는 아닙니다.

당시 Android 알림 채널은 기본 중요도(3)였습니다. 이 단계는 소리를 내지만 화면 위 팝업으로 끼어들지는 않습니다. 알림창 표시와 자동 화면 켜짐·잠금화면 팝업은 구분해야 하며 기기의 표시 설정을 따릅니다. [Android 공식 설명](https://developer.android.com/reference/android/app/NotificationManager#IMPORTANCE_DEFAULT)을 참고하세요. 기기 설정을 자동으로 변경하지 않았습니다.

Frontend 관련 시험 14건, 중계 시험 4건을 통과했습니다. 기기 식별값, 구독 주소·키, 계정 정보, 원시 로그와 운영 배포 스크립트는 공개하지 않습니다. 이미지 식별값은 [실행 버전 기록](RELEASE_BASELINE_20260918.md)에 있습니다.

## 선택적 제한 중계 구성

[중계 소스](../deploy/fcm_proxy.py)는 표준 Python 라이브러리만 사용합니다. `CONNECT fcm.googleapis.com:443`만 허용하고 다른 주소·포트·일반 HTTP 요청·DNS가 반환한 비공개 IP는 거절합니다. TLS 암호화 본문을 해독하거나 요청 본문·주소를 로그로 기록하지 않습니다. 동시 연결 수, 연결 시간과 전송량에 상한이 있습니다.

[Compose 예시](../deploy/fcm-proxy.compose.example.yml)는 **중계 컨테이너만** 생성하는 별도 예시입니다. 운영 환경의 복사본이나 기본 `docker-compose.yml`에 그대로 합칠 override가 아닙니다. 호스트 포트와 Docker 소켓을 열지 않고 비루트·읽기 전용으로 실행합니다.

설치자는 다음 조건을 먼저 마련해야 합니다.

1. 기존 Backend와 중계만 통신할 수 있는 신뢰된 내부망, Google에 연결 가능한 별도 외부 연결망, 검증한 Python 3.12 이상 실행 이미지의 digest를 지정합니다. `FCM_INTERNAL_NETWORK`, `FCM_EGRESS_NETWORK`, `FCM_PROXY_IMAGE` 값을 환경변수로 제공합니다. 이 예시는 망을 자동 생성하거나 기존 컨테이너를 변경하지 않습니다.
2. 예시를 단독으로 사용할 때는 공개 소스 루트에서 `docker compose -p mesil_push_relay -f deploy/fcm-proxy.compose.example.yml config`로 해석 결과를 먼저 확인합니다. 같은 명령의 `config`를 `up -d`로 바꾸면 중계만 시작됩니다. 실제 적용은 해당 기관의 승인·백업 절차를 따릅니다.
3. Backend의 기존 설정을 보존한 별도 배포 설정에서 `HTTPS_PROXY=http://fcm-proxy:3128`을 지정하고 위 내부망을 공유하게 합니다. 공개 예시가 이 변경을 자동 수행하지는 않습니다. 일반 `requests` HTTPS 호출에도 영향을 주므로 기존 HTTPS 서비스와 `NO_PROXY` 정책을 검토해야 합니다. 내부 AI용 HTTP 연결과 외부 AI 금지 설정은 그대로 유지합니다.
4. Web Push 활성화, 해당 설치가 직접 만든 VAPID 키, HTTPS 접속 및 브라우저 알림 동의가 별도로 필요합니다. 기존 운영 키·DB·구독 주소를 복사하지 마세요. 기본 공개 설치는 Web Push 비활성 상태를 유지합니다.
5. Backend에서 FCM 연결은 성공하고 다른 목적지는 거절되는지, 실제 기기에서 등록·시험 전송·알림 수신이 되는지 순서대로 확인합니다. HTTP 성공만으로 기기 수신을 완료 처리하지 않습니다.

이 중계는 Google FCM용입니다. 다른 브라우저 업체의 Push 주소까지 지원한다고 주장하지 않습니다. 구독 주소와 암호화된 일반 알림이 외부 알림 서비스로 전송되며, 외부 AI 전송과는 별개의 통신입니다. 기존 망의 전체 외부 통신 정책이나 개인정보 처리 기준을 대신하지 않습니다. 문제가 있으면 해당 환경의 기존 Backend 프록시 설정과 Frontend 이미지로 복귀하며 DB를 자동 복원하거나 낮은 버전으로 변경하지 않습니다.

## 공개 소스 표적시험

기존 Frontend 개발 의존성을 설치한 후 공개 소스 루트에서 실행합니다. 서버나 기기로 알림을 보내지 않는 로컬 시험입니다.

```powershell
node --test frontend/tests/push-recovery.test.mjs frontend/tests/push-settings-error.test.mjs frontend/tests/handwriting-review-confirmation.test.mjs
python deploy/test_fcm_proxy.py
```

제품 코드와 실제 배포된 중계 소스를 공개한 것이며, 구성 예시로 새 기관 전체 설치·운영 시험까지 완료했다는 뜻은 아닙니다. 기존 데모 영상·출처·라이선스 고지는 유지하고 새 외부 의존성이나 자산을 추가하지 않았습니다.
