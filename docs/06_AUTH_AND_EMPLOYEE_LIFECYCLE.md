# 인증·권한·입사·이동·퇴사 설계

## 인증

- Argon2로 비밀번호 해시 저장
- 무작위 세션 토큰 원문은 쿠키에만 전달
- DB에는 SHA-256 토큰 해시만 저장
- 쿠키: HttpOnly, SameSite=Lax, 운영 시 Secure
- 변경 요청은 허용된 Origin만 수락
- 같은 계정·접속지에서 15분 동안 5회 실패하면 이후 요청을 `429`로 제한
- 한 접속지에서 여러 계정을 합쳐 30회 실패해도 제한
- 원래 접속주소 대신 SHA-256 식별키를 실패기록과 세션에 저장

## 비밀번호와 로그인 기기

- 새 직원은 임시 비밀번호로 생성하고 첫 로그인에서 12자 이상 비밀번호로 변경한다.
- 임시 비밀번호 상태에서는 채팅·조직 API와 WebSocket을 사용할 수 없다.
- 본인이 비밀번호를 변경하면 현재 세션만 유지하고 다른 세션과 WebSocket을 종료한다.
- 사용자는 로그인된 기기를 조회하고 개별 종료하거나 현재 기기 외 모두 종료할 수 있다.
- 관리자가 임시 비밀번호를 재발급하면 대상 직원의 모든 세션과 WebSocket을 종료한다.
- 비밀번호 원문, 세션 토큰 원문, 접속주소 원문은 감사기록에 저장하지 않는다.

## 입사

관리자가 계정을 만들고 조직 FK를 지정한다. 전체 직원방과 사업부·부서·직종·층·팀 자동방 멤버십이 한 트랜잭션에서 생성된다.

## 이동

`PATCH /api/employees/{id}`가 조직정보를 바꾼 뒤 자동 멤버십을 재계산한다. 더 이상 해당하지 않는 자동 멤버십에는 `left_at`을 기록하고 새 자동 멤버십을 활성화한다. 지정방 수동 멤버십은 조직 이동으로 제거하지 않는다.

## 퇴사

1. `employment_status=terminated`
2. 모든 미폐기 세션에 `revoked_at`
3. 모든 활성 멤버십에 `left_at`
4. 감사기록 저장
5. DB 커밋 후 연결된 모든 WebSocket에 `force_logout`
6. 이후 로그인 `403`, 기존 API 세션 `401/403`

현재 관리자 자신을 화면에서 퇴사 처리할 수 없도록 차단한다.
