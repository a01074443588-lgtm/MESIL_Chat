# AI 챌린지 제출 시연 시나리오

## 1. 시연 목표

심사위원에게 단순한 채팅 앱이 아니라 다음 흐름이 실제로 연결된다는 것을
10분 안에 보여준다.

직원 보고 → 실시간 공유·읽음·댓글 → 업무함 수집 → AI 업무기록 초안 →
담당자 원문 대조·확정 → 인수인계·상담·장기요양 서류 후보

실제 SMCODI 공식서류 전송은 아직 연결하지 않았으며, 현재 화면은
`연결 가능한 검토 완료 자료`까지 보여주는 프로토타입이다.

## 2. 시연 계정

비밀번호가 포함된 실제 시연용 계정표는 Git에 포함하지 않는
`data/SUBMISSION_JUDGE_CREDENTIALS.txt`에서 확인한다.

| 역할 | 계정 용도 | 확인할 핵심 기능 |
| --- | --- | --- |
| 3층 요양보호사 작성자 | 휴대전화 A | 단순 입력, 어르신 우선목록, 메시지 전송 |
| 3층 요양보호사 수신자 | 휴대전화 B 또는 두 번째 브라우저 | 실시간 수신, 알림, 읽음, 댓글 |
| 시설 사회복지사 검토자 | PC | 업무함, AI 정리, 담당자 확인, 서류 후보 |

관리자 계정과 개발자 런처는 심사위원에게 제공하지 않는다.

## 3. 시연 전 준비

1. 현재 PC와 Docker, Cloudflare Tunnel을 켠다.
2. `https://chat.silvermedical.kr/api/health`가 `ok`인지 확인한다.
3. 휴대전화 A는 작성자 계정으로 로그인하고 `3층방`을 연다.
4. 휴대전화 B는 수신자 계정으로 로그인하고 알림을 허용한 뒤 앱을 닫아 둔다.
5. PC는 사회복지사 검토자 계정으로 로그인한다.
6. 세 기기 모두 실제 개인정보가 아닌 가명자료만 사용하는지 확인한다.
7. API 지연에 대비해 기존 AI 처리 완료 사례가 업무함에 보이는지 먼저 확인한다.

## 4. 권장 8분 시연

### 0:00~0:40 문제 설명

“현장 보고는 채팅, 종이, 음성으로 흩어져 있고 다시 서류로 옮기는 과정에서
누락과 중복업무가 생깁니다. MESIL_Chat은 직원 입력을 어렵게 만들지 않고,
뒤에서 업무자료로 정리해 담당자가 최소한만 확인하게 합니다.”

### 0:40~1:40 요양보호사 보고

휴대전화 A에서 `3층방`을 열고 어르신 목록에서
`시설(가명)004`를 선택한 뒤 다음 문장을 전송한다.

> 시설(가명)004 어르신이 점심을 평소의 절반 정도 드셨고 물은
> 100ml 드셨습니다. 입안 통증은 없다고 하셨습니다.
> 저녁 섭취량을 이어서 확인하겠습니다.

설명할 내용:

- 입력창은 어르신 선택과 짧은 보고에 집중되어 있다.
- 선택한 3층방에서는 3층 어르신을 먼저 보여준다.
- 전송과 동시에 원문이 보존되고 업무함 후보가 생성된다.

### 1:40~2:40 실시간 전달·알림·댓글

닫아 둔 휴대전화 B에 새 메시지 알림이 오는 것을 확인하고 앱을 연다.
새 메시지를 크게 열어 읽음 표시를 확인한 뒤 다음 댓글을 남긴다.

> 확인했습니다. 저녁 식사량과 수분 섭취량을 다시 확인하겠습니다.

설명할 내용:

- 같은 방 직원에게 WebSocket과 Web Push로 전달된다.
- 누가 읽었는지와 후속 댓글이 원문에 함께 남는다.
- 일반 채팅은 빠르게 유지하고, 필요한 보고만 업무함에서 처리한다.

### 2:40~5:40 사회복지사 업무함·AI 정리

PC의 사회복지사 계정에서 `업무함 → 처리할 대화`를 연다.
방금 생성된 `시설(가명)004` 사례를 선택하고 `AI로 자동 정리`를 누른다.

확인할 항목:

- 원문과 댓글이 수정되지 않고 위쪽에 보존됨
- 분류: 식사·영양
- 위험도: 관찰 필요
- 전달대상: 요양보호사·간호·사회복지사 후보
- 서류 후보: 급여제공기록지·통합사정
- AI 제공자와 담당자 미확정 안내

AI 응답이 늦거나 실패하면 기다리지 말고 기존 처리 완료 사례를 선택한다.

- 3층 낙상 의심: 안전·높음
- 4층 피부 발적: 건강·간호·관찰 필요
- 2층 식사량 감소: 식사·영양·관찰 필요
- 주간보호 반복 귀가요구: 일상생활·관찰 필요

### 5:40~7:00 담당자 확인·확정

사회복지사가 원문·댓글·AI 초안을 대조하고 검토 메모에 다음 내용을 적는다.

> 저녁 식사량과 수분 섭취량을 추가 확인하고 감소가 지속되면
> 간호·영양 담당자와 공유하기로 함.

`담당자 확인·확정`을 누르고 `서류 후보`에서 확정자료가 보이는지 확인한다.

설명할 내용:

- AI가 공식기록을 자동 확정하지 않는다.
- 담당자가 사실관계와 표현을 확인한 자료만 다음 단계로 이동한다.
- 원문, AI 초안, 담당자 확정문이 서로 분리되어 추적된다.

### 7:00~8:00 SMCODI 연결 방향

`서류 후보`의 문서 종류를 보여주며 다음과 같이 설명한다.

“현재는 급여제공기록지, 통합사정, 간호일지, 상담일지,
급여제공계획·결과평가에 사용할 수 있는 확인 완료 자료까지 만듭니다.
향후 SMCODI가 받을 API 계약이 확정되면 이 확정자료만 전송합니다.
챌린지 프로토타입에서는 실제 개인정보와 공식서류 자동반영을 차단했습니다.”

## 5. 심사위원 직접 체험

심사위원에게는 작성자 계정을 우선 제공한다.

1. `3층방`에서 가명 어르신을 선택한다.
2. 짧은 관찰내용을 작성한다.
3. 다른 화면에 실시간으로 표시되는 것을 확인한다.
4. 시간이 허용되면 사회복지사 검토자 계정으로 업무함을 확인한다.

수신자 계정은 발표자 기기에 미리 로그인해 두는 것을 권장한다.
사회복지사 검토자 계정은 AI와 담당자 확인 과정을 직접 눌러 볼 심사위원에게만
제공한다.

## 6. 실패 대비

- 공개 접속이 안 되면 `http://127.0.0.1:8080`의 로컬 화면으로 즉시 전환한다.
- 푸시가 늦으면 앱을 열어 WebSocket 실시간 수신을 먼저 보여준다.
- Nemotron이 형식 오류를 내면 Qwen 35B 자동 대체를 설명한다.
- AI 응답이 30초를 넘으면 미리 처리된 4개 가명 사례로 전환한다.
- OCR은 비교검증 중이므로 이번 핵심 시연에서는 필수 단계로 넣지 않는다.
- 실제 SMCODI 전송 화면이 없다는 점을 숨기지 않고, 확정자료와 API 경계를
  보여주는 것으로 마무리한다.

## 7. 시연 성공 기준

- 작성자가 3층방과 3층 어르신만 자연스럽게 찾을 수 있다.
- 수신자에게 새 메시지가 실시간 또는 푸시로 도착한다.
- 읽음과 댓글이 원문에 연결된다.
- 업무함에 새 자료가 생성되고 원문이 보존된다.
- AI가 분류·위험도·전달대상·서류 후보를 제안한다.
- 담당자 확정 후 서류 후보에서 확인된다.
- 실제 개인정보·관리자 계정·개발자 런처가 노출되지 않는다.
