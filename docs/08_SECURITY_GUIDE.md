# 보안지침

## 반드시 지킬 항목

- `.env`와 시험계정 파일을 Git에 커밋하지 않는다.
- 운영에서 `COOKIE_SECURE=true`, HTTPS, 강한 관리자 비밀번호를 사용한다.
- 검색엔진 차단 헤더와 메타태그는 보조수단이며 인증을 대체하지 않는다.
- DB·백업·첨부파일 디렉터리를 웹서버 정적 경로로 공개하지 않는다.
- 퇴사·권한변경 감사기록을 보존한다.
- 실제 어르신 개인정보는 일반 채팅에 무분별하게 입력하지 않는다.

## 현재 보안구현

- 서버측 권한검사
- Argon2 비밀번호 해시
- 세션 토큰 해시 저장
- Origin 허용목록과 CORS 자격증명 제한
- 퇴사 즉시 세션·멤버십·WebSocket 차단
- 로그인 실패 시간창·횟수 제한
- 임시 비밀번호 강제 변경과 12자 최소길이
- 비밀번호 변경·관리자 초기화 시 다른 세션과 WebSocket 폐기
- 본인 로그인 기기 조회·개별 종료·일괄 종료
- 외부 공개 포트를 Caddy 한 곳으로 제한하는 Docker 구성
- 개발자 사용자 전환 런처의 별도 쿠키·짧은 전환세션·감사기록·재직자 제한
- 개발자 런처가 켜진 제출본을 실패시키는 `check-release-safety.ps1`
- 운영환경의 HTTPS 전용 출처·보안쿠키·신뢰 게이트웨이를 백엔드 시작 시에도 강제
- SilverHome 운영용 Caddy 자동 HTTPS·HSTS·검색노출 차단·내부 포트 격리
- 로컬 Whisper 서비스의 공유토큰 인증과 원본 음성의 외부 API 미전송
- Web Push 구독을 사용자와 현재 로그인 세션에 함께 연결하고 로그아웃·세션폐기·퇴사 시 전송 제외
- 잠금화면 푸시에 메시지 원문·방 이름·직원명·어르신명을 넣지 않는 최소정보 알림
- VAPID 개인키를 `data/runtime`에만 저장하고 Git·웹 정적경로·로그에서 제외
- 만료되거나 해지된 푸시 주소는 응답상태와 연속 실패횟수에 따라 자동 비활성화

개발자 런처는 개발 중 반복 로그인 편의만 제공한다. 전환한 사용자에게 새로운 방 권한이나 관리자 권한을 추가하지 않으며, 제출 전 `DEV_LAUNCHER_ENABLED=false`로 바꾸고 안전점검을 통과해야 한다.

## 휴대전화 알림 보안

- 브라우저가 발급한 푸시 주소와 공개키는 알림을 보낼 수 있는 접근정보이므로 일반 화면·로그·백업 보고서에 노출하지 않는다.
- 서버는 푸시를 보내기 직전에 사용자 재직상태와 로그인 세션 유효기간·폐기여부를 다시 확인한다.
- 채팅 전송은 푸시 사업자 장애와 분리한다. 알림 실패 때문에 메시지 저장이나 실시간 채팅이 취소되지 않는다.
- VAPID 개인키를 새 서버로 옮길 때는 환경파일과 함께 별도 보안경로로 이전하며, 노출 의심 시 새 키를 발급하고 기존 구독을 다시 받는다.

## 운영 전 보강

- `.env.production.example`을 `.env.production`으로 복사하고 모든 `CHANGE_ME`를 강한 임의값으로 변경
- `check-release-safety.ps1 -EnvPath .\.env.production` 통과
- 실제 서버 방화벽은 SSH 관리포트와 80/443만 허용하고 DB 포트는 외부 비공개
- 기관 상황에 맞는 실패 제한값과 비밀번호 정책 확정
- 관리자 2단계 인증 검토
- 백업 암호화와 외부 안전보관
- 감사로그 조회·보존기간
- 침투시험·취약점 점검
