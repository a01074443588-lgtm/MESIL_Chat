# 케어포·SMCODI 어르신 명단 입력 경계

## 목적

SMCODI_CHAT은 케어포 기관정보를 변경하지 않는다. 관리자가 이미 로그인한 정당한 기관 세션에서 현재 명단을 읽기 전용으로 확인하고, 화면과 채팅 데이터베이스에는 실명 대신 가명만 저장한다.

실명과 가명의 연결표는 이 PC의 Git 제외 로컬 파일에만 둔다. 채팅·OCR·음성에서 실명이 언급되면 서버가 로컬 연결표로 가명 어르신 후보를 찾지만, 직원 화면과 외부 제출용 프로토타입에는 실명을 노출하지 않는다.

## 현재 구현

2026-07-27 현재 시설 케어포에서 재원 어르신 49명과 재직 직원 38명을 읽기 전용으로 확인했다. 어르신은 `시설(가명)001` 형식, 직원은 `시설직원(가명)001` 형식으로 변환했다.

- 채팅 데이터베이스 반영: 시설 가명 어르신 49명
- 층별 확인: 2층 7명, 3층 14명, 4층 14명, 5층 14명
- 직원 가명 기준표: 시설 직원 38명
- 주간보호·방문요양: 케어포 로그인 전이므로 아직 확보하지 않음

시설 명단이 반영된 뒤에는 채팅의 어르신 선택 목록과 일반 관리자 화면에서 기존 시설 연습자료를 숨기고 케어포 기반 가명 49명만 사용한다. 기존 연습자료는 과거 메시지 연결을 보존하기 위해 DB에서 삭제하지 않는다.

직원 가명 기준표를 채팅 로그인 계정과 자동으로 합치지는 않는다. 같은 이름·퇴사자·겸직자를 잘못 연결하면 방 권한이 달라질 수 있으므로, 직원 계정 연결은 이후 관리자 확인 화면에서 한 명씩 승인하는 별도 단계로 둔다.

`scripts/prepare_smcodi_resident_lexicon.py`는 UTF-8 JSON 또는 CSV를 읽어 `data/smcodi_residents.local.json`을 만든다. 이 파일은 Git에서 제외되며 OCR 이름 후보에만 사용한다.

관리자 화면의 `어르신 명단 가져오기`는 같은 JSON/CSV를 실제 채팅 어르신 명단과 비교한다. 업로드 직후 DB를 바꾸지 않고 다음 항목을 보여준다.

- 신규: SMCODI에는 있고 채팅 명단에는 없는 어르신
- 정보 변경: 이름·서비스·층·생활실·이용상태가 달라진 어르신
- 이용 중지: 기존 SMCODI 관리 명단에는 있으나 새 파일에는 없는 어르신
- 변경 없음: 현재와 같은 어르신
- 확인 필요: 중복 식별자, 없는 층, 필수값 누락 등 자동 반영하면 위험한 항목

관리자가 체크한 `신규·정보 변경·이용 중지`만 `선택한 변경 승인·반영`으로 처리한다. 체크하지 않은 항목은 보류되고, 확인 필요 항목은 선택할 수 없다.

받는 필드는 다음으로 제한한다.

- `external_id`: SMCODI 쪽 식별자
- `display_name`: 현재 표시 이름
- `service_type`: 시설·주간보호 구분
- `floor`: 층
- `room_name`: 생활실 또는 주간보호 구역
- `is_active`: 현재 이용 여부

가명 형식 예시는 `data/smcodi_residents.example.json`에 있다.

```powershell
python scripts\prepare_smcodi_resident_lexicon.py `
  D:\승인된내보내기\smcodi_residents.json
```

## 관리자 사용 순서

1. SMCODI_CHAT에서 `관리 → 어르신 관리`를 연다.
2. 시설·주간보호·방문요양 중 `명단 준비됨`으로 표시된 서비스의 `최신 명단 확인`을 누른다.
3. 새로 추가·정보 바뀜·이용 중지·직접 확인 건수를 본다. 이 단계에서는 아직 실제 명단이 바뀌지 않는다.
4. 새로 추가·정보 바뀜 항목을 확인한다. 이용 중지는 자동 선택하지 않으므로 관리자가 직접 체크한다.
5. `선택한 N명 저장하기`를 누른다.
6. 같은 화면 위쪽의 `현재 어르신 명단`에서 `케어포 확인 명단` 인원과 가명·층을 확인한다.

가명 연습파일을 불러오는 메뉴와 과거 연습파일 작업명은 일반 관리자 화면에서 숨긴다. 같은 실제 명단이라 바뀐 사람이 없으면 선택·저장영역을 보여주지 않고 `저장하거나 선택할 것은 없습니다`로 끝낸다.

화면을 처음 열 때 완료된 과거 기록은 자동으로 펼치지 않는다. 필요할 때만 `지난 작업 보기`에서 선택한다. 가명 시험 모드는 파일에 없는 기존 어르신을 이용 중지 후보로 만들지 않는다.

동명이인과 이름변경은 표시이름이 아니라 `external_id`로 구분한다. 동기화로 만들어진 어르신은 내부적으로 `SMCODI:{external_id}` 식별자를 사용한다. 이 접두어가 없는 수동·시험 어르신은 새 파일에 없더라도 자동 이용중지 후보가 되지 않는다.

## 저장과 안전장치

- 업로드 원본 파일은 서버에 보관하지 않는다.
- 파일명, SHA-256 요약값, 내보내기 시각, 비교 건수, 승인자와 승인시각만 남긴다.
- 미리보기 뒤 현재 정보가 달라지면 반영을 중단하고 새 미리보기를 요구한다.
- 이용중지는 삭제가 아니라 비활성 처리이며 기존 메시지·업무기록 연결을 유지한다.
- 시설·주간보호의 층이 활성 조직정보와 정확히 일치하지 않으면 `확인 필요`로 차단한다.
- 빈 파일은 전체 퇴소로 오인될 위험 때문에 거부한다.

## 현재 검증 경계

시설 가명 49명의 미리보기·관리자 승인·실제 명단 반영·서버 재시작 후 유지까지 확인했다. 데이터베이스 층별 집계도 케어포 화면의 7·14·14·14명과 일치했다.

주간보호와 방문요양은 해당 서비스 케어포 로그인이 필요하다. 로그인하지 않은 상태에서 기존 연습자료를 실제 명단으로 간주하거나 추정 인원을 생성하지 않는다. 현재 작업은 자동 주기 동기화가 아니라 관리자가 케어포 명단을 확인하고 승인하는 수동 갱신 방식이다.

## 채팅에서 진화하는 기관용어

어르신 명단과 별개로 `scripts/update_chat_lexicon.py`가 현재 채팅 DB의 단어빈도를 다시 계산해 카카오 기관용어와 합친다. 이 작업은 메시지를 보낼 때 실행하지 않으므로 요양보호사 입력을 지연시키지 않는다. 직원명과 현재 어르신명은 업무용어 집계에서 제외하고, 결과에는 원문 문장이 아니라 단어와 횟수만 저장한다.
